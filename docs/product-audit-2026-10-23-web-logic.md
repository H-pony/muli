# 2026-10-23 产品逻辑审核：共享播放、搜索与下载

范围：Windows/macOS 桌面客户端内部复用的 TypeScript、播放界面与服务端接口。Android 与 Apple 使用各自的原生实现，见分端报告。未新增独立 Web/PWA 交付物，未回滚工作区原有修改。

## 已修复的闭环问题

| 问题 | 修复后行为 |
| --- | --- |
| 搜索缓存只按 URL 区分，同地址来源重导入/改名后返回旧 key/name，后续详情或换源无法定位 | 搜索缓存包含来源身份、名称、详情地址与成人标记；详情缓存同样包含来源身份 |
| 流式搜索没有收到结束事件却返回成功空数组，覆盖已收到的结果 | 缺少 `done` 明确报连接中断，交由搜索页保留结果并重试 |
| 异常搜索 body / 来源字段可能抛出服务错误 | 对关键词和来源结构先校验，返回 400；取消信号贯通搜索与详情请求，中断结果不进入缓存 |
| 打开新剧集会继承上一集历史位置/时长；加载失败也覆盖最近观看集数 | 历史仅在真实播放产生有效进度后写入；按剧集合并，旧集迟到回调不能更新新集 |
| 看完仅清 progress 表，history 仍留片尾，无法区分刚开始与已完成 | `completeEpisode` 事务清进度并标记 `completed`；历史、详情与首页使用一致的下一集/重播选择规则 |
| 显式重播 0 秒被当成“没有恢复参数”，仍恢复本地旧断点 | 观看 URL 保留 `position=0`，它优先于 IndexedDB；导入只有历史时可从历史位置续播 |
| HLS manifest 早于媒体时长就绪，恢复只尝试一次而失效 | 等待 loadedmetadata / durationchange 再恢复，每集只完成一次；播放中代理回退/重建与设置切换保留当前秒数 |
| 换集期间旧媒体事件读取新 props，将旧片位置写进新剧集；结束标记未按集清零 | 回调绑定当前媒体所属剧集，换集前落盘旧集，重建未恢复前不写进度，按集清零结束状态 |
| 自动下一集 800ms 内手动切集或关自动播放，旧定时器仍跳转 | 手动选集、身份变化、设置关闭及卸载都取消旧定时器 |
| 换源按标题前缀命中续集/外传，目标少集数时静默跳第 1 集 | 同名忽略标点匹配；缺当前集明确提示；同集换源携带当前播放秒数；失败/未配置来源保留错误与重试入口 |
| 直连分享无 CMS ID，却被视为缺少来源；其历史把 URL 作为 CMS ID 请求详情 | 直连独立播放并保存 directUrl；历史重开使用 URL 参数；兼容旧 URL-as-ID 记录 |
| 历史清空确认关闭后残留，下次打开直接出现；未使用保存的来源地址恢复来源 | 关闭历史层清确认状态，链接使用历史来源地址；删除撤销/导入保留原时间与完成状态 |
| 下载暂停后“继续”重新选文件又直接返回，任务无法继续 | 同页面暂停恢复原任务和保存流；刷新/失败才重新选择目标 |
| 全局仅一份保存目标，多个排队任务互相覆盖 | 保存目标按任务 ID 分别保存，最多 3 个任务占用运行名额 |
| 刷新后状态仍是下载中，但没有运行句柄，用户无法恢复 | 初始化把未结束任务转为可恢复暂停，保留网络分片断点 |
| 取消被视为成功 resolve，可能报下载完成；暂停取消一直等待；清单请求无法取消 | 取消贯穿清单与分片，唤醒暂停等待，reject 取消并 abort 文件目标，禁止完成提示 |
| 8 个线程恢复只有 1 个分片时，领取序号越界 | 在异步暂停检查之后同步检查/领取分片编号 |
| 一个下载线程失败后，另一个缓存写入仍回报下载中、取消后晚写孤儿分片 | 任一失败中止所有线程，写入前后验 signal，allSettled 等全部退出后才交还句柄并清理取消分片 |
| 文件选择 API 丢失 Window receiver，可能意外降级内存保存 | 保留 receiver 调用系统文件选择器 |

## 验证

- 使用 `fake-indexeddb` 验证逐集历史、迟到回调、完成后重播、导入/撤销时间以及非有限媒体值。
- 使用 mock HTTP 验证搜索来源身份缓存隔离、非法请求、流截断与明确空结果。
- 使用模拟 Cache Storage 和保存目标验证 8 线程单分片恢复、暂停取消、解析前取消，以及线程失败后等待迟到写入退出。
- 相关扩大回归：播放恢复、预取器、M3U8、历史迁移、URL 与详情播放选择。
- TypeScript 类型检查与修改文件 ESLint 完成；具体最终计数由本轮总审核报告记录。

## 验证边界

本报告记录代码审查与受控回归，不把 mock 网络当作真实源可播放证明。真实来源连续播放、代理回退后的实测定位、系统文件选择器与大文件保存、各原生设备端验收仍由本轮主审核结合现有构建执行；未在这里声称已完成这些设备结果。
